# 运行测试并分析结果

## 步骤

1. **识别项目类型与测试入口**——先看有哪些文件在，据此决定跑什么，不要凭猜：
   - `pyproject.toml` / `setup.py` / `tox.ini` → Python：优先 `python -m pytest -q`
   - `package.json` → Node：看 `scripts` 里有没有 `test`
   - `go.mod` → `go test ./...`
   - `Cargo.toml` → `cargo test`
   - `pom.xml` / `build.gradle` → Maven / Gradle
   - 多个都存在时，优先跑改动涉及的那个
2. **先跑全量**——拿到整体基线：通过多少、失败多少、跳过多少。
3. **失败逐个定位**，每个失败都要回答三个问题：
   - 断言失败在哪一行、期望值与实际值分别是什么
   - 是**测试写错了**还是**被测代码错了**——读相关源码与测试本身来判断，不要默认是代码错
   - 这个失败是本次改动引入的，还是本来就存在的
4. **区分失败类型**——编译/导入错误、断言失败、超时、环境缺失（缺依赖、缺服务）处理方式完全不同。环境问题要明确指出并给出安装/启动命令，不要去改测试来绕开。
5. **给出结论**，格式如下：
   - **失败清单**：`测试名 — 原因 — 归属（代码缺陷 / 测试缺陷 / 环境问题）— 修复建议`
   - **通过情况**：通过数 / 总数
   - **下一步**：建议先修哪个，为什么

## 注意

- 不要为了让测试变绿而删除或跳过测试用例
- 不要修改测试的断言来迁就当前实现——除非你能论证是测试写错了
- 测试跑得久时不要中途放弃；超时的话说明是哪条用例卡住
- 只报告你实际观察到的结果，不要编造没跑过的测试结果
